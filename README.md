# Speech Emotion Recognition Through Various Models

> **A deep-learning project for recognizing human emotions from speech
> using acoustic feature extraction, data augmentation, and a deep 1D
> Convolutional Neural Network.**

## 🎙️ Project Overview

Human speech contains much more information than words alone.

Changes in:

-   Pitch
-   Energy
-   Voice intensity
-   Spectral characteristics
-   Speaking patterns

can provide useful clues about the emotional state of a speaker.

This project explores **Speech Emotion Recognition (SER)** by
transforming raw speech recordings into numerical acoustic features and
using a deep neural network to classify the emotional content of the
speech.

The notebook brings together several stages of an end-to-end audio
machine-learning pipeline:


The repository also contains the principal visualizations and

# ⚠️ An Important Implementation Detail

There are **two feature-extraction definitions** in the notebook.

The training pipeline uses:

``` text
13 MFCCs
+
ZCR
+
RMSE
```

with the extracted feature vector resulting in:

``` text
1,620 features
```

The later inference function defines another
`mfcc()`/`extract_features()` implementation and reshapes the result to:

``` text
1 × 2376
```

This means the notebook contains a preprocessing inconsistency between
the principal training pipeline and the later inference helper.

For a production deployment, these two pipelines should be unified so
that the exact same feature-generation procedure is used during training
and inference.

This README intentionally documents the notebook as implemented rather
than silently correcting that discrepancy.

# ⚠️ Limitations and Considerations

Despite the high test accuracy, several aspects should be considered
before interpreting the result as a production-ready SER system.

## 1. Dataset Combination

The project combines four datasets collected under different recording
conditions, speakers, environments, and dataset-specific conventions.

Therefore, the model may learn dataset-specific acoustic characteristics
in addition to emotional characteristics.

------------------------------------------------------------------------

## 2. Speaker Independence

The notebook uses a random train/test split:

``` python
train_test_split(
    X,
    Y,
    random_state=0,
    test_size=0.2,
    shuffle=True
)
```

It does not explicitly perform a speaker-independent split.

For a stronger evaluation, speakers should ideally be separated between
training and testing.

------------------------------------------------------------------------

## 3. Augmentation and Data Leakage Risk

The notebook creates multiple augmented versions of each original
recording **before** performing the train/test split.

Consequently, augmented versions originating from the same original
recording can potentially appear in both training and testing sets.

This can make the reported test accuracy more optimistic than a strict
speaker- and recording-independent evaluation.

A stronger experimental design would:

``` text
Original recordings
        ↓
Train/Test split
        ↓
Augment training data only
```

------------------------------------------------------------------------

## 4. Class Imbalance

The combined dataset is not perfectly balanced.

In particular:

``` text
Surprise = 652 original recordings
```

while several other emotions have around:

``` text
1,900+ recordings
```

Although the final classification metrics are strong, class-level
analysis remains important.

------------------------------------------------------------------------

## 5. Inference Feature Mismatch

As noted earlier, the later inference helper produces a feature shape
of:

``` text
2376
```

while the main training pipeline uses:

``` text
1620
```

This should be resolved before deploying the model.

------------------------------------------------------------------------

# 🚀 Potential Improvements

A more rigorous version of this project could investigate:

### Speaker-Independent Evaluation

Use speaker IDs to ensure that speakers in the test set never appear in
training.

### Stratified Splitting

Maintain a more controlled class distribution between train and test
sets.

### Augmentation After Splitting

Apply augmentation only to the training partition.

### Compare Architectures

Systematically compare:

``` text
MLP
LSTM
CNN
CNN-LSTM
GRU
Transformer
```

using the same preprocessing and evaluation protocol.

### Hyperparameter Optimization

Tune:

``` text
Number of filters
Kernel sizes
Learning rate
Batch size
Dropout
Number of layers
Dense-layer size
```

### Cross-Validation

Perform speaker-aware cross-validation rather than relying on one random
split.

### Robust Inference Pipeline

Create one shared preprocessing function used by both:

``` text
Training
Inference
```

to eliminate feature-shape inconsistencies.

### Real-Time Recognition

Extend the model to process microphone input:

``` text
Microphone
    ↓
Audio buffer
    ↓
Feature extraction
    ↓
CNN
    ↓
Emotion
```
